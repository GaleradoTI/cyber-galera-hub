- Event links reuse `events.location_or_link` for the external event page, while `online_link` is the meeting URL and `address` is the physical location; this preserves existing rows without schema changes.
- Password recovery uses server-issued one-time codes and the existing Resend connection; locate users by profile email then verify Auth email (fallback to Auth for unsynced changes), and report failed delivery rather than treating it as success.- Phone push uses a push-only worker (public/push-sw.js, no caching) + push_subscriptions; a notifications insert trigger calls /api/public/push/send via pg_net, which re-reads the row by id and dedupes with pushed_at — why: no shared secret needed and the bell stays the single source of alerts.
- The installable app is manifest-only (start_url /login) and the idle-session guard is skipped in standalone mode — why: user wants app users to stay signed in.
- Admin users list reads the admin_users_overview view (profile + roles + badges) via the service role — why: one query instead of three.
- Ambassador (EMBAIXADOR) access is per-user via `ambassador_permissions.areas`, enforced by `has_ambassador_permission()` RLS policies and mirrored in the UI by `useAmbassadorCan()` — why: admins choose what each ambassador manages.
- Notification preferences are applied by a BEFORE INSERT trigger on notifications (muted category = row dropped; push-muted = pushed_at prefilled) using `notification_category()`, mirrored in `src/lib/notification-meta.ts` — why: one gate for bell and push.
- Event reminders run hourly via SQL-only pg_cron (`send_event_reminders`), deduped by `event_reminders_sent`.
